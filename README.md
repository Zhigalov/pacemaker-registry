# Реестр пейсмейкеров

Реестр выступлений пейсмейкеров: импорт результатов, фильтр по соревнованию,
рейтинг, PostgreSQL и контейнер для деплоя в Yandex Cloud.

На странице `/add` можно вставить публичную ссылку на результат участника
RussiaRunning или results.runc.run. Backend получает имя, мероприятие, дистанцию, chip time, темп и
контрольные точки. После проверки результат можно сохранить в PostgreSQL.

Схема создаётся при старте приложения и содержит:

- `pacemakers` — уникальные пэйсмейкеры по фамилии и имени;
- `events` — соревнования с идентификатором источника, типом времени и настройками рейтинга;
- `race_results` — результаты, выбранное время флага и контрольные точки в JSONB.

## Рейтинг соревнования

Карточки главной имеют одинаковые размеры: название и дистанция, цель и факт
в формате ЧЧ:ММ:СС с отклонением в секундах верхним индексом у чип-тайма,
три независимо окрашенные оценки. Строки времени и оценок используют общую
сетку; ширина карточки — 18rem, на узких экранах ограничена шириной окна.
Пиктограммы снабжены текстовыми пояснениями; отсутствие оценки темпа показано
серым «—», а не нулём. Форматирование не меняет исходные данные и расчёты.

Наведение на карточку результата показывает краткие подробности. Клик открывает
`/results/{id}`: все сохранённые отсечки без ограничения по высоте, данные
выступления, ссылки на соревнование и исходный результат. Графики финиша и темпа
используют текущие настройки соревнования в режиме только чтения — наведение
показывает баллы, редактирования и сохранения нет.
На графике финиша нанесено фактическое отклонение от флага, на графике темпа —
оценка каждого корректного отрезка с подписью километровой отсечки.
Координаты берутся из тех же расчётов, что и рейтинг, без округления целевого темпа.
Шкала расширяется для больших отклонений; подписи разведены даже при совпадении
точек. Наведение, касание или фокус на подписи показывает отклонение со знаком
и балл. Кнопка «Обратно к списку»
сохраняет фильтры `event_id`, `min_events` и `include_splits`. На телефоне карточка
открывается обычным касанием; переход работает и без JavaScript.

Страница `/events` показывает список соревнований с графиками без редактирования.
На странице выступления `/results/{id}` можно раскрыть «Изменить время на флаге»
и сохранить новую цель в формате ЧЧ:ММ (больше нуля). Пересчитываются целевой темп,
отклонения, оценки и метки графиков; главная использует новую цель при следующей
загрузке. Чип-тайм, отсечки, тип времени и формулы соревнования не меняются.
При параллельном редактировании устаревшая форма не перезаписывает новое значение:
нужно проверить текущую цель и повторно подтвердить сохранение.

Она доступна из верхнего меню рядом с добавлением результата.
Страница `/events/{id}` показывает название и тип времени. Здесь сохраняется
единственная формула оценки финиша для всех результатов этого соревнования:

- зелёные ворота допуска — 10 баллов;
- соседние жёлтые зоны — линейное изменение между 10 и выбранным баллом на границе (по умолчанию 8);
- красные хвосты — экспоненциальное снижение, отдельно настраиваемое с каждой стороны.

Для саб-минуты границы по умолчанию: −45, −10, +10, +45 секунд.
Для ровного времени: −60, −15, 0, 0 секунд: справа жёлтая зона выключена,
экспонента начинается сразу от 10. Ширина жёлтой зоны определяет наклон;
масштаб падения и кривизна управляют красными хвостами. Ноль недостижим.
Границы, оценки на стыках и резкость меняются на графике, все параметры доступны также в полях.
Ось времени равномерная: прямые и экспоненты не искажаются сменой масштаба
внутри зон, в том числе во время перетаскивания. Левый и правый граничные
баллы независимы (0,1–10). При нулевой ширине жёлтой зоны экспонента начинается
от 10; сохранённый граничный балл используется при расширении зоны.
Ранее сохранённые формулы без граничных баллов читаются с прежними значениями 8.

Настройки хранятся в `events.rating_config` (JSONB), а не в браузере.
Если настройки ещё не сохранены, применяются значения по умолчанию для типа
соревнования. Миграция при запуске добавляет nullable-колонку без изменения результатов.

### Темп на отрезках

На той же странице отдельный блок «Оценка за темп на отрезках» сохраняет
настройки только для этого соревнования в `events.pace_rating_config` (JSONB).
Формула финиша сохраняется независимо. POST `/events/{id}/pace-rating`
принимает семь числовых полей: `tolerance`, `checkpoint`, `bad`,
`checkpoint_score`, `bad_score`, `decay`, `curve`.

Шкала симметрична относительно целевого темпа; границы задаются в с/км.
По умолчанию: допуск ±5 — 10 баллов, ±10 — 9, ±30 — 7, между опорными
точками линейное снижение, далее экспонента с масштабом 15 с/км и кривизной 1.
Это сохраняет прежние оценки, пока настройки соревнования не изменены.
Границы, баллы и резкость можно менять перетаскиванием точек графика или
числами, кривизну — числом или ползунком. Сервер проверяет порядок границ
и невозрастание баллов. Сброс заполняет форму значениями по умолчанию;
для применения нужно нажать «Сохранить темп».

Оценки темпа по-прежнему взвешиваются по длинам отрезков. Требуется покрытие
не менее 80% дистанции; иначе в итог входит только оценка финиша.

На главной результаты рассчитываются по формулам своих соревнований. Пейсеры
отсортированы по среднему рейтингу видимых выступлений, округлённому до десятых,
как на карточках. При равной отображаемой оценке
выше пейсер с большим числом выступлений за всю историю, затем —
с меньшим средним абсолютным отклонением финиша от цели по видимым выступлениям.
При полном равенстве порядок определяется именем, затем ID.
Фильтр «Минимум выступлений» (целое число от 1, по умолчанию 1) учитывает все
выступления за всю историю, включая разные дистанции одного соревнования,
независимо от выбранного соревнования. Имя URL-параметра `min_events` сохранено
для совместимости ссылок. Повторное добавление того же результата по-прежнему
блокируется уникальным идентификатором источника.
Чекбокс учёта темпа
включает составную оценку: 60% финиш и 40% темп по отрезкам. При недостаточном
покрытии отсечками используется только финиш. Старые параметры `rating_mode`
и `custom_rating` больше не используются.

## Локальный запуск через Docker

```bash
docker compose up --build
```

После запуска:

- страница: <http://localhost:8080/>
- liveness: <http://localhost:8080/health>
- PostgreSQL readiness: <http://localhost:8080/ready>

## Запуск без Docker

Нужны Python 3.12+ и `uv`:

```bash
uv sync --extra dev
cp .env.example .env
uv run uvicorn pacemaker_registry.main:app --reload
```

## Аналитика посещений

В production задаётся `YANDEX_METRICA_ID=113525433`. Без корректного числового
ID скрипт не подключается; отправка разрешена только с `pacersreg.ru`.
Счётчик асинхронный и не влияет на работу форм при блокировке Метрики.
Вебвизор, карты кликов, запись заголовков и автоматическое отслеживание
внешних ссылок отключены. Из URL просмотров удаляются параметры и якоря;
для внешнего реферера сохраняется только домен. Имена, значения полей и
ссылки на результаты не передаются в пользовательских событиях.

Цели типа «JavaScript-событие» в Метрике:

| Идентификатор | Что означает |
| --- | --- |
| `result_open` | Открыта детальная карточка выступления |
| `registry_filter` | Изменён один из фильтров реестра |
| `result_parse` | Отправлена форма получения результата |
| `result_preview` | Данные успешно получены и показаны для проверки |
| `result_saved` | Новый результат успешно сохранён (не дубликат) |

Цели описывают браузерные действия, не заменяют аудит БД: блокировщик может
не отправить событие, а повторная загрузка страницы — повторить просмотр.
