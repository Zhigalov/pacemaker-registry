## Размещение

- Ubuntu 24.04, `standard-v3`, 2 vCPU × 20%, 2 ГБ RAM, 10 ГБ SSD в `ru-central1-d`.
- nginx завершает HTTPS и проксирует на Docker `127.0.0.1:8080`.
- Docker-образ текущего релиза закреплён по digest, а не плавающему тегу.
- Используется **та же** приватная PostgreSQL; копии базы и локальной БД нет.
- Существующий сервисный аккаунт приложения сохранён: pull образов и чтение
  конкретного секрета Lockbox; дополнительные IAM-роли не выдавались.
- Пароль забирается при запуске в root-only `/run/pacers/app.env` (tmpfs).
  Его нет в metadata, cloud-init, Git или локальных артефактах.
- Контейнер не имеет доступа к metadata API, root filesystem read-only,
  capabilities сброшены, память и журналы ограничены.
- Наружу доступны 80/443; SSH ограничен проверенными IP оператора `/32`.
  При смене сети добавлять только согласованный адрес. HTTP-сервисы определения IP
  могут показывать адрес прокси: не расширять правило до `0.0.0.0/0`.
- Старая инфраструктура (Serverless, `min_instances=1`, API Gateway, сеть,
  база и Lockbox) не удалялась и не выключалась. Добавлено только одно правило
  БД: порт 6432 из группы временной ВМ.

Все идентификаторы и исходные DNS-записи — в `resources.json`. Он не содержит
секретов. Публичный IP зарезервирован, поэтому сохраняется при остановке ВМ.

## Обслуживание

`cloud-init.yaml` — начальная установка Docker/nginx с существующим публичным
SSH-ключом вместо `__SSH_PUBLIC_KEY__`. SSH host key обязательно сверить с
fingerprint в Compute serial console; не отключать StrictHostKeyChecking.

Установка/повторная установка (без изменений DNS):

```sh
python3 ops/temporary-vm/install.py \
  --host 84.252.135.179 --known-hosts /path/to/verified-known-hosts \
  --revision bba1hgjnjta5ivi16jic --certificate fpqupotov0gtue2d0uhv
```

TLS-сертификат скопирован из Certificate Manager, закрытый ключ передан только
через проверенное SSH-соединение, хранится root-only. Копия на ВМ сама не
обновляется: действует до **4 января 2027, 12:48 UTC**. Если временный режим
затянется, до этой даты повторить установку с обновлённым сертификатом или
организовать его обновление. ACME DNS-записи Certificate Manager сохранены.

Проверки: `systemctl is-active pacers nginx`, HTTPS `/health`, `/ready`, главная,
`/events`, `/add`, карточка выступления. Не выводить `docker inspect` целиком,
`app.env`, certificate content или IAM-токены. Пароли и ключи не коммитить.

Пока DNS направлен на ВМ, обычный Serverless-деплой **не обновляет публичный
сайт**. При следующих изменениях обновить образ на ВМ и проверить его отдельно;
не считать успешный деплой в Serverless завершённой публикацией.

Обновление приложения без переустановки ВМ:

1. Сохранить свежий `pg_dump` и проверить чтение архива через `pg_restore`.
2. Сохранить root-only копию `/etc/pacers/config.json`. Изменить **только** `image`
   на digest проверенного образа; сохранить окружение и ссылки Lockbox.
3. Выполнить `sudo python3 /opt/pacers/prepare.py`: заранее загрузить образ,
   не останавливая работающий сайт. Не выводить файл окружения.
4. В новом образе с существующим `--env-file /run/pacers/app.env` выполнить
   `python -m pacemaker_registry.migrate`. Миграции больше не запускаются
   автоматически при старте приложения.
5. Перезапустить `pacers`, проверить `/ready`, главную, фильтры, подробности,
   `/events` и `/add` через публичный домен. При сбое вернуть сохранённую
   конфигурацию образа, подготовить runtime и снова запустить старый контейнер.

DNS, nginx/TLS, IAM, сеть и Serverless при таком обновлении не меняются.

## Возврат после восстановления облака

Не запускать автоматически только по статус-борду: сначала проверить весь
старый путь с доменом, TLS, приложением и БД, не только прямой `/health` контейнера.

1. Проверить Serverless `/ready`, страницы и API Gateway через его актуальный IP
   с `curl --resolve pacersreg.ru:443:<gateway-ip> https://pacersreg.ru/ready`.
   Не использовать `-k`. Убедиться, что версии приложения согласованы.
2. `python3 ops/temporary-vm/switch_dns.py --to serverless` — dry run;
   затем с `--apply`. Скрипт проверяет текущие записи и восстанавливает исходные
   ANAME/CNAME одним запросом. ACME/NS/SOA не затрагиваются.
3. Дождаться истечения DNS TTL и проверить `pacersreg.ru` и `www` через обычный
   DNS. Оставить ВМ доступной на период перехода. При необходимости вернуть
   `switch_dns.py --to vm --apply`.
4. После подтверждения восстановления и согласования удаления убрать только
   временную ВМ `fv435m0kn12bvqiqcgnu` (её boot disk auto-delete), правило БД
   `enpsocpd1vd7bi1uurtk`, группу `enpsa4fepsqt7ar80pbe` и зарезервированный
   IP `fl8ock45ephquvuh1ppp`. Проверить отсутствие диска `fv4cnluu88osv4mnmlk8`.
   Не удалять подсеть, сервисный аккаунт, PostgreSQL, сертификат или Serverless.
5. Обновить этот документ и `resources.json`: временный режим завершён.

Остановка ВМ прекращает плату за CPU/RAM, но диск и IP продолжают оплачиваться.
Никаких автоматических задач на удаление ресурсов не создавалось.
